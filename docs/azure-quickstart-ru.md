# Пошаговый запуск проекта в Microsoft Azure (самый простой путь)

## Что именно будем делать

Размещаем **весь проект на одной Linux-виртуальной машине Azure**. Docker Compose запускает четыре контейнера: Nginx (frontend + API gateway), Quiz API (FastAPI), Results API (FastAPI) и PostgreSQL. Это самый прямой вариант для учебного проекта, потому что текущий `docker-compose.yml` уже связывает сервисы во внутренней Docker-сети.

Для этого пути не нужны Azure Container Apps, Azure Kubernetes Service, Azure Database for PostgreSQL, Azure Container Registry или отдельный Static Web Apps. Их можно изучать позже, но сейчас они добавят настройки и потенциальные расходы.

**Сложность:** примерно 3/5, если уже умеешь пользоваться терминалом; 4/5, если впервые создаёшь VM. Сам Docker-запуск — 1–2/5. Создание VM и настройка сетевого доступа — наиболее непривычная часть.

**Стоимость:** не гарантируется бесплатной. Цена зависит от подписки, региона, размера VM, диска, IP и трафика. Перед созданием открой Cost Management / Pricing Calculator и проверь, покрываются ли выбранные ресурсы кредитом или бесплатной квотой. Установи бюджетные уведомления. Оповещения не являются жёстким лимитом расходов. После проверки проекта останови или удали ненужные ресурсы; остановка VM не обязательно прекращает плату за диск/IP.

## Часть A. Проверить проект на своём компьютере

1. Установи Docker Desktop с официального сайта Docker. На Windows при необходимости включи WSL 2 и перезагрузи компьютер.
2. Распакуй архив проекта.
3. Открой терминал в корневой папке проекта, где находится `docker-compose.yml`.
4. Создай локальный файл настроек:

   **Windows PowerShell:**
   ```powershell
   Copy-Item .env.example .env
   ```

   **macOS/Linux:**
   ```bash
   cp .env.example .env
   ```

5. Открой `.env`. Для локального запуска оставь `HTTP_PORT=8080`. Замени `POSTGRES_PASSWORD` на длинный пароль и укажи тот же пароль в `DATABASE_URL`. В URL пароль должен совпадать с `POSTGRES_PASSWORD`.
6. Запусти контейнеры:
   ```bash
   docker compose up --build -d
   ```
7. Посмотри состояние и логи:
   ```bash
   docker compose ps
   docker compose logs --tail=100
   ```
8. Открой `http://localhost:8080`. Проверь, что тест загружается, можно выбрать ответы, отправить тест и увидеть историю результатов.
9. API-документация: `http://localhost:8080/api/quiz/docs` и `http://localhost:8080/api/results/docs`.
10. Остановить проект: `docker compose down`. Команда `docker compose down -v` дополнительно удалит локальный том PostgreSQL и сохранённую историю результатов — не используй её, если данные нужны.

Если команда не работает, проверь, что Docker Desktop запущен, терминал открыт в папке с `docker-compose.yml`, а порт 8080 не занят другим приложением.

## Часть B. Создать виртуальную машину Azure

1. Открой https://portal.azure.com/ и войди в свой аккаунт. Если аккаунта нет, начни с официальной страницы https://azure.microsoft.com/pricing/purchase-options/azure-account/ и прочитай условия выбранного предложения.
2. В поиске портала открой **Resource groups** → **Create**.
3. Выбери подписку, укажи имя `rg-cloud-practitioner`, выбери регион и нажми **Review + create** → **Create**.
4. Открой **Virtual machines** → **Create** → **Azure virtual machine**.
5. Выбери созданную Resource Group, назови VM `vm-cloud-exam`, выбери Ubuntu LTS и подходящий небольшой размер. До создания обязательно проверь оценочную стоимость и доступность размера в выбранном регионе.
6. Для доступа выбери SSH public key, если доступен, и сохрани приватный ключ в безопасном месте. Не присылай его в чат и не загружай в репозиторий.
7. В правилах входящего трафика разреши **SSH (22) только с твоего IP** и **HTTP (80) из интернета** для учебной демонстрации. Не добавляй правило на порт 5432. Если мастер предлагает открыть SSH для всех адресов (`Any`), измени источник на `My IP` или свой конкретный IP/CIDR.
8. Создай VM. Дождись состояния Running и скопируй её Public IP address.

Названия некоторых полей в Azure Portal могут отличаться в зависимости от версии интерфейса. Не создавай дополнительные платные ресурсы, если они не нужны для этого варианта.

## Часть C. Установить Docker на Ubuntu VM

Подключись по SSH к IP VM, используя имя пользователя и SSH-ключ, заданные при создании. В терминале локального компьютера команда выглядит примерно так:

```bash
ssh -i /path/to/private-key.pem azureuser@PUBLIC_IP
```

На Windows путь к ключу будет другим; имя `azureuser` замени на фактическое имя пользователя. Не публикуй приватный ключ.

В терминале VM выполни:

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2 git
sudo systemctl enable --now docker
sudo docker --version
sudo docker compose version
```

Если пакет `docker-compose-v2` не найден в образе, используй актуальную официальную инструкцию Docker для своей версии Ubuntu: https://docs.docker.com/engine/install/ubuntu/ .

## Часть D. Передать проект на VM

Самый простой вариант — если архив уже есть на компьютере, передать его по SCP. Выполняй эту команду **на своём компьютере, а не внутри SSH-сессии**:

```bash
scp -i /path/to/private-key.pem aws-cloud-practitioner-exam.zip azureuser@PUBLIC_IP:~/
```

Пути к архиву и ключу, имя пользователя и IP замени на свои. Если архив находится в другой папке, укажи полный путь. Альтернатива — клонировать свой Git-репозиторий, если он уже создан и не содержит секретов.

Затем в SSH-сессии VM:

```bash
sudo apt-get install -y unzip
unzip ~/aws-cloud-practitioner-exam.zip -d ~/
cd ~/aws-cloud-practitioner-exam
```

Проверь, что в этой папке находится `docker-compose.yml`:

```bash
ls
```

## Часть E. Настроить и запустить приложение

1. Создай `.env`:
   ```bash
   cp .env.example .env
   nano .env
   ```
2. В `.env` установи:
   - `POSTGRES_PASSWORD` — уникальный длинный пароль;
   - `DATABASE_URL` — тот же пароль в URL подключения к `postgres`;
   - `HTTP_PORT=80` — чтобы Nginx публиковался на стандартном HTTP-порту VM.
3. Не публикуй `.env` и не добавляй его в Git. Для учебной работы пароль хранится в файле на VM; для production следует применять менеджер секретов и усилить защиту.
4. Запусти:
   ```bash
   sudo docker compose up --build -d
   ```
5. Проверь состояние:
   ```bash
   sudo docker compose ps
   sudo docker compose logs --tail=100
   ```
6. На самой VM проверь gateway:
   ```bash
   curl http://localhost/health
   ```
   Ответ должен содержать статус `ok`. Можно проверить API:
   ```bash
   curl http://localhost/api/quiz/health
   curl http://localhost/api/results/health
   ```
7. На своём компьютере открой `http://PUBLIC_IP`, подставив настоящий публичный IP VM. Если сайт не открывается, проверь входящее правило TCP/80 в Network Security Group, `HTTP_PORT=80`, статус контейнеров и логи Nginx.

## Часть F. Проверить работу и подготовить демонстрацию

- Открой сайт с публичного IP.
- Начни тест, ответь на вопросы и отправь ответы.
- Убедись, что отображается итоговый балл.
- Открой историю результатов и проверь, что запись появилась.
- Покажи преподавателю `docker compose ps`, структуру проекта, два FastAPI Swagger UI и схему архитектуры в `docs/architecture.md`.

## Важно о безопасности и HTTPS

В этой простой конфигурации сайт будет доступен по HTTP, а не HTTPS. Она подходит для первичной учебной проверки, если условия задания допускают HTTP. Не используй её для конфиденциальных данных или реального production-приложения. Для HTTPS настрой домен и reverse proxy с сертификатом (например, Caddy) или другой поддерживаемый Azure вариант. Не открывай PostgreSQL наружу; в Compose порт БД не опубликован. Ограничь SSH своим IP.

## Остановка и удаление ресурсов

На VM, в папке проекта:

```bash
sudo docker compose down
```

Контейнеры остановятся, но том PostgreSQL останется на VM. Не используй `-v`, если хочешь сохранить историю результатов.

Когда проект больше не нужен, открой Azure Portal → Resource groups → `rg-cloud-practitioner` и проверь её содержимое. Если хочешь полностью прекратить связанные расходы, удали ненужные ресурсы/группу после того, как сохранишь всё нужное. Удаление Resource Group удаляет содержащиеся в ней ресурсы и данные. Сначала убедись, что в ней нет ничего другого, что нужно сохранить.

## Типичные ошибки

- **Сайт не открывается:** проверь Public IP, правило inbound TCP/80, `HTTP_PORT=80`, затем `sudo docker compose ps` и логи.
- **Контейнеры перезапускаются:** выполни `sudo docker compose logs --tail=200` и проверь `.env`.
- **Ошибка подключения к БД:** `POSTGRES_PASSWORD` и пароль в `DATABASE_URL` должны совпадать. Если БД уже инициализировалась с прежним паролем, изменение переменной не меняет пароль в существующем томе автоматически.
- **Порт занят:** измени `HTTP_PORT` на свободный порт и открой соответствующий порт в NSG только для тестирования; стандартный вариант для публичного сайта — 80.
- **Мало памяти:** выбери VM с достаточной RAM или останови другие процессы; не запускай лишние сервисы.
- **Нужно пересобрать после изменения файлов:** `sudo docker compose up --build -d`.
